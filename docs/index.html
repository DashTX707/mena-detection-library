03 / THE PIPELINE

How each file is built

The same workflow a human CTI & detection team would run — applied consistently, and re-runnable by any contributor. Provenance is recorded in every pack.

STAGE 01
cti-expert

Extract

Reads the source reporting and MITRE profile; extracts TTPs, tooling, procedures and IOCs with a detection-feasibility read on each.

STAGE 02
decision-agent

Route

Splits every technique into a detection lane or a hunt lane — judged on feasibility, not on how alarming the actor is.

STAGE 03·A
detection-engineer

Author Sigma

Writes behavior-based Sigma for the detection lane, validated with sigma-cli — 0 errors across the library.

STAGE 03·B
threat-hunter

Write hunts

Turns the hunt lane into falsifiable hypotheses with data sources, a query starting point, and triage guidance.

04 / INSIDE A FILE

Everything an analyst needs, per actor

Deployable content plus the provenance to trust it — not a wall of orphan rules.

  • detections/
    Sigma rules
    Behavior-based, ATT&CK-tagged, CI-validated. Convert to Splunk, Sentinel/KQL, or Elastic with pySigma.
  • hunts/
    Hunt hypotheses
    Hypothesis, required telemetry, a query to start from, and what a true vs. false positive looks like.
  • ttps.md
    ATT&CK mapping
    Full technique map + a lane-colored Navigator layer per actor.
  • iocs/
    Sourced indicators
    Defanged, typed, and cited to the originating advisory or report.
  • intel/
    Provenance
    cti-pipeline.json + routing.json — how every rule was derived, open for audit.

MENA Detection Library

The deployable companion to the MENA Threat Actor Tracker: the tracker answers who targets the region; this library answers how to detect and hunt them.

Aggregates publicly available reporting for defensive use only. Contains no stolen data, credentials, or live malware — only detection logic and pointers to public sources. Verify time-sensitive detail against primary reporting before operational reliance.
